# Corrected private transfer preparation

This preparation supplies thin source-capture, staging and receiving adapters.
No actual cohort, trace, model, generator, SVD, optimizer, scientific checker,
renderer, QA review, package, download or upload was executed during preparation.
All actual corrected science, reproduction, visual review and remote handoff
evidence must exist later. Test fixtures are tiny fictional byte files and
injected processes; they confer no scientific or release approval.

The immutable originals and their negative/failed findings remain separate.
The correction is labelled post-hoc rank conditioning after original failures
were known. The adapters create their own manifests and external process
captures; they do not reuse an original855 completion certificate as corrected
certification. The selected reproduction is the frozen original92 union pilots,
not whole-grid numerical reproduction. The actual selected union size can exceed92.

## Entry points

Every CLI takes an explicit own `--preparation-receipt` and its byte SHA,
`--request` and its byte SHA, and `--python` for the actual same-file interpreter.
All five numeric thread variables must already equal1. Interpreter symlinks are
resolved only to establish actual same-file identity; immutable evidence paths
and every ancestor remain unlinked. Use the frozen Apple Silicon environment.

* `capture_corrected_source.py` records one of three fixed read-only source
  prerequisites: receiving reproduction comparison, reporting replay, or factual
  claims. It never launches the execution/resume reproduction controller.
* `stage_corrected_extensions.py` takes `--output` for a new private payload.
  It verifies all prerequisites before creating a hidden copy attempt, delegates
  the original safe copier/no-replace publisher and creates clean119/855 Git
  source archives. It neither packages nor uploads anything.
* `verify_restored_correction.py --mode transport --output NEW_EXTERNAL_DIR`
  delegates the byte-pinned original `verify.py` through an isolated explicit
  source bootstrap. Its trusted canonical inventory SHA comes from the owned
  release record. Transport success alone says nothing about corrected science.
* `verify_restored_correction.py --mode science --output NEW_EXTERNAL_DIR`
  performs fresh sealed mixed-v2 `--verify-existing`, receiving-only selected
  reproduction comparison and deterministic reporting/claim replay in order.
  It writes genuine subprocess captures and its final receipt outside all
  restored and baseline inputs. There is no numerical repair or resume route.

Example future source-capture invocation (placeholders are not runnable evidence):

```sh
"$LOCKED_PYTHON" -I -B "$ADAPTER/capture_corrected_source.py" \
  --preparation-receipt "$ADAPTER/preparation_receipt.json" \
  --preparation-receipt-sha256 "$ADAPTER_RECEIPT_SHA" \
  --request "$SOURCE_CAPTURE_REQUEST" --request-sha256 "$REQUEST_SHA" \
  --python "$LOCKED_PYTHON"
```

The same common arguments apply to staging and receiving, with their explicit
output/mode arguments. Root builds and reviews the request bindings from actual
sealed files. Helpers never invent scientific review records or a visual
attestation. The machine-readable exact role surface is in `interface_contract.json`.

## Receiving evidence and preserved paths

Restored input JSON remains byte-identical, including historical absolute path
text. New external bindings explicitly resolve those roles to the payload and
separately restored frozen sources/baselines. No search or automatic path repair
is used. Current reporting files, old captured claim stdout, both renderer
sources, selected pass, correction manifest, QA and sidecar must resolve to their
exact staged locations. Only explicitly verified frozen external roles can hold
baseline/explanation/source files. A byte-identical original working tree is
refused as a substitute for the fresh restore.

The receiving reader verifies selected scientific samples and retained terminal
recipe evidence, including actual original producer provenance distinct from a
later official cached comparison. It never executes `run_reproduction.py` or
fits/reconstructs a new terminal recipe. Its sole possible child is the fresh
frozen259-package environment checker. Mixed replay independently recomputes
stored diagnostics and forecast scores through the sealed verifier, without
fitting. Reporting replay reproduces deterministic table/JSON/claim bytes and
preserves the source visual review without issuing a new approval.

Actual child exit codes, stderr/stdout and ordered commands are captured
externally. Source and fresh remote receipts are distinct. A self-written
scientific receipt is not rc0 proof. The final receiving receipt binds every
fresh output byte and the exact immutable payload. Root still records actual
remote private-release identity, fresh download provenance and publication;
these helpers always leave overall programme completion false.

## Failure handling and storage

All files use the unchanged byte-pinned write-once IO. Closed, fsynced temporary
bytes are atomically linked without replacement; failures retain diagnostic
attempt bytes. Staging retains failed hidden copy attempts. Receiving/source
capture retains actual nonzero/launch-error logs and emits no success receipt
for an invalid final child summary. A committed receipt followed by cleanup,
source mutation, extra/residual inventory or ownership failure is not CLI
success. Existing outputs are never repaired or overwritten; choose a new
root-reviewed destination after diagnosis.

Root must measure actual source tree sizes and destination free space before
launch. Distinct retained trace copies increase logical payload size. APFS clones
can reduce local physical use only where the original safe copier supports them;
cross-volume copy, compressed shards, source download and a separate fresh
restore still require physical storage. The prep does not claim a final byte
budget or select an external drive automatically.

## Validation boundary

The accompanying tests exercise tiny complete/partial grids, all three selected
routes, failure/orphan retention, trace/code mutation, wrong actual commands,
typed rc0, failed publication/launch, exclusive output, symlink/JSON refusal,
source/output overlap, restored-role relocation, immutable-byte changes,
incomplete/synthetic proof refusal and original transport delegation. All child
invocations are injected. The production CLI exposes neither dependency injection
nor alternate study counts. Failed preparation checks and subsequent fixes are
preserved with exact start/finish source hashes. Ruff, AST/compile and JSON checks
do not run scientific code. The sealed preparation receipt reports the final
validated bytes and leaves all actual evidence and peer review separate.
